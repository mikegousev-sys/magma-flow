# Память беседы: скорость, уровень и расход шлака по видео (сентябрь 2026)

Ветка `claude/upbeat-hypatia-bk6p7i` (репозиторий `mikegousev-sys/magma-flow`).
Пожелания пользователя: крайне кратко; при нехватке данных — спрашивать, не решать вслепую; перепроверять.

## Цель
Измерение скорости, уровня и расхода шлака (ПВП) в жёлобе по видео камеры MV-MIPI-SC130M
(1280×1024, до 214 fps) на Raspberry Pi 5; совместимость с C++ `magma_vision` (NDJSON, порт 9100).

## Установка и геометрия
- Камера ~3.5 м, ~52° от горизонтали. Видна половина жёлоба, вторую закрывает стенка.
  Край потока — рваная застывшая корка, заходит на зеркало на ~25 мм.
- Профиль (чертёж + xlsx): дуга R150 до касания на 92.6 мм (полуширина 138.58), далее прямые
  стенки 22.5° от вертикали до 135 мм (полуширина 156.15, ширина ~31 см). Выше 135 мм —
  нерабочая зона, расплав не доходит; полная глубина жёлоба 33 см. `analysis/gutter_profile_R150.csv`.
- Калибровка 19.09 (сетка на поверхности): 0.548 мм/px вдоль, 0.638 поперёк.
- Разметка 29.09: камеру ПЕРЕСТАВЛЯЛИ, изображение повёрнуто на 180° (imgdir 3 против 0).
  Меловые метки — путь по стенке от середины дна, см, шаг 5. По меткам 10–20 см:
  0.47–0.51 мм/px вдоль, β определяется плохо (40–49°), поперёк 0.60–0.77 мм/px —
  `analysis/calib/calib_2026-09-29.json`. Для уровня нужен прямой замер масштаба поперёк.
  Размер «П» на борту — пользователь уточнит позже.
- Реальный выпуск: 160–180 т шлака за плавку 1.5–2 ч. ρ = 3400 кг/м³, k = 0.67–0.85.

## Python (`analysis/`)
- `flow_speed.py` — скорость 5 методами (фаза, PIV, Farneback, LK, kymo), консенсус.
- `flow_rate.py` — ось, край корки (`crust_edges`), полуширина → уровень → площадь → расход.
- `collect_metrics.py` — сводка по записям.
- `series_flow.py`, `vision_series.py` — поточный расчёт сериями по 10 кадров (бюджет 0.2 с на RPi5),

- `tests/`: `vision_protocol_check.cpp` + `check_lines.py` (разбор отчётов C++-парсером),
  `cpp_replay.cpp` + `cpp_feed.py` (прогон записей через C++-алгоритмы без камеры).
- `calib/`: `chessboard_A4_30mm.png`, `calib_marks.py`, `calib_2026-09-29.json`.

## C++ (`code/`, правки только в «дополнении», ядро не трогалось)
- Причины сбоя уровня в старом C++: полоса выходила за кадр (Sample=0 → ложная кромка),
  модель двух кромок при видимой половине, абсолютные пороги, одиночные кадры,
  профиль только дуга до 105, β=31, заглушка `center_reference_px`.
- Сделано (коммит 2196c31): `magma_edge.hpp` — отсчёты за кадром NaN, относительный порог;
  `magma_level.hpp` — стенки `geometry.wall_angle_deg`; новый `magma_axis_level.hpp` —
  уровень «ось + край»; `magma_vision.cpp` — `level.mode = axis_edge`, ключи `level.axis.*`;
  `magma_vision.conf` — под установку 19.09.
- Не сделано по решению пользователя: `FlowConfig.mm_per_px` из калибровки (зашито 0.5333).
- Замечено: при длине полосы скорости 1280 px GCC-PHAT занижает скорость (1.4 против 2.0 м/с),
  при 900 — норма. Причина не выяснена.
- На 18:47:59 ось упирается в верхний край кадра → unreliable; камеру стоит направить так,
  чтобы ось была на ~1/4 кадра от края.
- Сборка: `g++ -std=c++20 -Wall -Wextra -Wpedantic -O2` без предупреждений. Pi: `mike@192.168.137.165`.
